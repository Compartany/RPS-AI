# RPS-AI · 石头剪刀布 自适应 AI

一个纯前端的「石头剪刀布」对战程序：AI 会记录**被预测者**的出招习惯，用多种统计标准预测其下一招，并不断按应验率修正各标准的权重。

支持两种模式（对战区**右上角**的按钮切换）：

| 模式 | 谁在出招 | AI 干什么 |
| --- | --- | --- |
| **对战模式** | 你 vs AI | 预测「你」的下一招，并自己出招 |
| **辅助模式** | 你（我方）vs 真人（界面里称「对手」） | 不亲自出招，直接指定我方本轮出哪招（＝预测对手的招后挑最优应对） |

- 键位、统计口径完全一致，只有「被预测者」不同：对战模式预测**你**，辅助模式预测**对手**（真人）。
- 辅助模式下，AI 直接给定我方出招，你只需在赛后补录**对手**的招。
- 界面称谓随模式整体切换（**辅助模式下不会出现「电脑」字样**）：

| 界面位置 | 对战模式 | 辅助模式 |
| --- | --- | --- |
| 上方（对手出招） | 电脑 | 对手 |
| 下方（我方出招） | 你 | 我方 |
| 左侧评估卡片 | 人类不可预测性评估 | 对手不可预测性评估 |
| 分析面板标准名前缀 | 人类前 N 招 / 电脑前 N 招 | 对手前 N 招 / 我方前 N 招 |
| 记分板 | 电脑胜率 / 你的胜率 | 对手胜率 / 我方胜率 |

> 第一次尝试完全用 AI 开发一个小玩具。AI 说我确实是作者，真的吗？

## 运行

无需构建，直接用浏览器打开 `index.html` 即可（双击也行）。

## 玩法

**对战模式**（默认）：

- 上方是电脑，下方是你的三个出招按钮（键盘 `1` / `2` / `3` 同效）。
- 每局开始电脑已先选好招，你点击后同时揭示并判定胜负。
- 上一轮回顾：电脑出招格**右侧的小格**（1/4 大小）显示它上一局出的招；你上一局出的那个按钮**右下角**会标出「赢 / 平 / 输」（绿 / 灰 / 红）。

**辅助模式**：

- **上方是对手（真人），下方是我方**。
- **下方三颗按钮会高亮我方本轮的出招**，点击可改选（不听 AI 推荐、改出别的招）；不改就按 AI 推荐出。若 AI 暂时没有可信依据，则标「暂无可信依据」（那一招是随便挑的，但依旧照出、照样计入胜负与统计）。
- 对手出完后，点上方「对手出了」的 ✊ / ✋ / ✌ 补录对手的实际出招（键盘 `1` / `2` / `3` 同效），录完**立刻结算**并进入下一局。
- 进入该模式会**默认展开分析面板**（方便边出边看预测依据）。

**两种模式共用**：

- 顶部记分板：**对手胜率 / 我方胜率**（均只按**非平局**计算）+ 双色对比条；下方一行为 `对局 · 当前连势 · 平局率 · AI 预测命中率 · 最优胜率`。命中率只显示**半衰期加权**的单值，全部统计等细节在悬停提示里。
- 点「显示分析面板」可展开右侧表格：每个标准的当前依据、历史计数、预测、应验率与权重。
- 底部「对局记录」：色块（绿=我方胜 / 红=对手胜 / 灰=平）+ 最近 10 局统计，悬停看详情。
- **两种模式的数据与参数各自独立**：各自一套对局记录、统计、模型与滑块/开关参数，切换模式时整包对调、切回来原样保留（想重来用「重置数据」，它只清当前玩法这一套）。

## AI 策略

AI 把每个「标准」当成一个独立专家，各自统计「在这种局面下**被预测者**会出什么」：

| 标准 | 含义 |
| --- | --- |
| 整体频率 | 你的总体出招偏好 |
| 人类前 N 招 | 你自己最近连续 N 招的**出招序列** |
| 电脑前 N 招 | 电脑最近连续 N 招的**出招序列** |
| 人类胜负 N | 你最近 N 招之间的**胜负关系序列**（每招相对自己上一招） |
| 电脑胜负 N | 你最近 N 招相对电脑相应招的**胜负关系序列** |
| 随机基线 | 不看任何信息、每次均匀随机，命中率**恒为 1/3**；作为衡量其它标准的基准 |

- 记忆阶数固定为 **3**。从 1 到 3 的每个阶数都是**独立标准**。
- 每个标准内部按具体键值（如 `✊→✌️`）分别计数（带时间衰减，面板里取整展示）。
- **同时包含两类维度**：`出招序列`（如 `✊→✌️`）与`胜负关系序列`（如 `胜 → 负 → 平`，计数与预测也按胜 / 负 / 平呈现）。
- N=1 时的「电脑胜负 1」即「上一局的胜负」，所以不再单列「上局结果」。
- 标准列表可在**权重**（默认，按面板上那条占比降序）/ **应验率** / **默认顺序**之间切换；「随机基线」也参与排序。
- 面板「权重」列是**归一化占比**：所有参与合成的标准合计为 100%（不够 1/3 的标准为 0）。
- 预测时用拉普拉斯平滑得到各标准的人类出招分布，再按 `max(0, 应验率(收缩后) − 1/3) × 样本置信度` 加权求和；**应验率不超过 1/3（随机基线）的标准权重为 0，不参与合成**。
- **时间衰减**（参数「记忆半衰期」，默认 16 局，可自动调）：每学一局，旧计数与应验统计先乘一次 `0.5^(1/hl)`，半衰期 `hl` 局后权重减半；`0` = 不遗忘。这样「近期习惯」会逐渐压过「很久以前的习惯」。
- **记忆半衰期的自动调参**：5 个档位（不遗忘 / 64 / 32 / 16 / 8 局，取 2 的幂使档位在对数尺度上均匀）**各自维护一份独立模型**同时学习同一份历史，比较各自的**预测命中率**（每个档位按自己的半衰期加权，短记忆只看近期表现），取最近 40 局窗口，**从最长记忆开始挑，只有明显更优（+3%）才升级到更短的记忆**；面板底部实时展示各档位命中率。
- **样本收缩**（参数，默认 1.0，可自动调）：应验率按 `1/3 + (应验率 − 1/3) × n/(n + z)` 向随机基准收缩（z = 收缩强度，0 = 直接用原始应验率），样本越少越保守。「向基准收缩」而非置信下界，可保证高于 33% 的标准始终有正权重，不会出现所有标准一起归零、AI 失去依据的情况。样本置信度为 `n/(n+1)`（n = 当前局面的样本数），折扣较宽，让应验率在小样本阶段就能尽早参与权重。
- **样本收缩的自动调参**：不靠启发式，而是**比命中率**——每局让各档位（0 / 0.5 / 1 / 1.5 / 2）在同一局面下各自给出预测，赛后统计各自的**预测命中率**（统一以当前半衰期为权重基准）；取最近 40 局窗口，**从最小收缩开始挑，只有当更大收缩的命中率高出 3% 以上时才升级**，否则一路退回 `0`（完全按应验率加权）。样本不足 12 局时保持当前值，参数每局最多移动一档。面板底部实时展示各档位命中率。
- 电脑出招 = 在综合分布上**期望收益最高**（赢概率 − 输概率）的招，而不是简单地克「最可能的一招」——避免在预测不确定时反而送分。
- **探索扰动**：当预测不明确或历史应验率低时，会以一定概率随机出招，避免被人类反向针对。该概率由「探索强度」设定为**保底值**（默认 10%）；自动调参**不直接比较胜率，而是先做显著性检验**：设 $w$ 为「按最优出招」的胜率，$\sigma=\sqrt{w(1-w)/n_{eff}}$（剔除平局、按半衰期加权取 Kish 有效样本量，并用 Agresti-Coull 平滑），$z=(1/3-w)/\sigma$，上限 $\varepsilon_{\max}=\mathrm{clamp}((z-1)/2,0,1)$——即 $z\le1$ 时完全不随机、$z\ge3$ 时完全随机。这样「预测本来就不可靠」不会被误判成「被针对」，而真被死克时（$w\to0$）仍会迅速拉满。**此外，开局几局证据不足，随机度会被临时拉高**（约 11 局内逐步回落到常规水平）——否则极少样本给出的偏斜（「AI 总是出某个招」）很容易被人类快速摸清。
- **押注判定**（不受「自动调参」开关影响）：**「最优招」是 `argmax` 这种确定性函数**——只要预测分布的排序固定（哪怕差距只有千分之一），AI 就会长期出同一招，人类看一眼就能反制。所以只有当 AI 的**预测命中率显著高于随机基准 1/3** 时才押注最优招，否则**改按预测分布取样**：仍是同一份预测，但出招不再是确定值，边际分布等于预测分布，观察不出固定规律。判定与探索上限同一套口径（Agresti-Coull 平滑 + Kish 有效样本量 + 单侧 $z$ 检验，取最近 40 局窗口），只是方向相反：$z=(w-1/3)/\sigma$，押注概率 $=\mathrm{clamp}((z-1)/2,0,1)$——即 $z\le1$（命中率与 1/3 无显著差别）时完全不押注、$z\ge3$（命中率显著更高）时全押，中间线性过渡。面板底部「押注判定」实时展示 $w$ / $n_{eff}$ / $z$ / 押注概率。

### 可调参数（面板底部「策略参数」）

| 参数 | 作用 |
| --- | --- |
| 自动调参 | **默认开启**。α / 样本收缩 / 记忆半衰期 / 探索强度均由对局数据自动调整；其中样本收缩与记忆半衰期按「各档位的预测命中率」择优（收缩统一以当前半衰期为权重基准，半衰期各自按自身半衰期加权），探索强度则由「按最优出招胜率是否显著低于 1/3」的显著性检验决定上限 |
| 平滑系数 α | 拉普拉斯平滑强度。α 越小越激进地相信少量样本 |
| 样本收缩 | 应验率的保守程度（默认 1.0，自动调参范围 0~2）。0 = 直接用原应验率，越大越不信任小样本 |
| 记忆半衰期 | 旧样本的遗忘速度（默认 16 局；自动调参档位 0 / 64 / 32 / 16 / 8）。0 = 不遗忘，越小越只看近期习惯 |
| 探索强度 | 「纯随机出招」的保底概率（默认 10%）；自动调参档位 0 / 10 / 20 / 35 / 50 / 70 / 100%。0 = 完全利用（最容易被针对性套路） |
| 启用探索扰动 | 总开关，关掉后 AI 不再做均匀随机；出招仍受「押注判定」约束（预测不显著时按预测分布取样） |

> **押注判定**是独立于上述参数的安全机制（不可关）：预测没被证明有用时，AI 不会用「靠噪声排出来的最优招」冒充主见，而是按预测分布出招。

关闭「自动调参」后，α 与探索强度可手动拖动；开启时两项由数据自动控制（滑块暂锁）。面板底部有「恢复默认参数」按钮，可把上述参数复位。改动 α 或重算都会回放全部历史重新评估各标准的应验率。

## 随机数

项目里所有随机（探索扰动、随机破平局、NIST 标定的对照序列）都走同一套无偏工具：

- **来源**：`crypto.getRandomValues()`（操作系统熵源），不用 `Math.random()`；仅当环境不支持时才退回后者。
- **无偏整数**：`randInt(n)` 用**拒绝采样**。源的字节范围 0~255 不能被 3 整除（256 % 3 = 1），直接 `% 3` 会让 0、1 比 2 多出 1/256 的概率；丢掉尾部零头后完全无偏。
- **洗牌**：随机破平局用 **Fisher–Yates**，不用 `sort(() => Math.random() - 0.5)`——后者的结果分布并不均匀（受排序算法实现影响）。

> 背景：`rand() % 3` 这类写法虽然常用，但既引入模偏差，又会把 LCG 的低位缺陷搅匀而掩盖问题；换成直接取低位则立刻崩（详见实测对比）。

## 人类不可预测性评估

面板中部会把 AI 自己的 **预测命中率** 当尺子，给你的出招随机性打分（100 为随机基准、**可超过 100**，越高越接近真随机、越难被 AI 抓）：

- **评分**：`100` = 命中率与随机基准（1/3）持平或略低（`z ∈ [−0.5, 0)`）。`z > 0`（命中率高于 1/3）按 `100 − 40 × z` 扣分（最低 0，正侧不留死区）；`z < −0.5`（命中率明显低于 1/3）按 `100 + min(50, (−0.5 − z) × 40)` 加分（最高 150）。其中 `z = (命中率 − 1/3) / √((1/3)(2/3)/n)`。真随机（z ≈ 0）= 100；z = 0.39（命中率 37%）≈ 84；z = −1 ≈ 120；z = 1.5 ≈ 40；z ≥ 2.5 归零。用标准误而非固定比例，样本越多越稳。
- **AI 预测命中率**：AI 预测下一招命中被预测者实际出招的比例（与出招方实际出什么招无关，即不受探索扰动影响）；对战模式下即「AI 对你下一招的预测命中你实际出招」。此处**按半衰期加权**计算（近局权重更大）；半衰期为 0（不遗忘）时等同全部统计。
- **最大可预测优势**：各标准里「收缩后应验率」最高的那一条（小样本会被压向 1/3，避免噪声误报），也就是你最容易被抓住的破绽；优势不足 1% 时显示「没有明显破绽」。
- **出招分布**：✊ / ✋ / ✌ 的出现比例，仅作直观参考。

样本不足 12 局时不评估。实测：真随机、以 45% 概率重复上一招等对手类型下，评分与 AI 实际命中率完全同步。

## NIST SP 800-22 随机性检测

点顶部「**NIST 检测**」按钮会弹出完整报告（默认隐藏）。它测的是**你的出招序列有多像真随机**——也就是「你的手够不够随机、有多容易被 AI 抓住」，并给出一个 **0~100 的人类随机性评分**。

报告会把你的人类出招序列编码成比特流，跑整套 **15 项** NIST 检验（累积和拆成正向 / 反向，共 16 行）：
频率、块内频率、游程、最长 1 游程、二元矩阵秩、离散傅里叶变换、非重叠 / 重叠模板匹配、通用统计（Maurer）、线性复杂度（Berlekamp-Massey）、序列、近似熵、累积和 ×2、随机游走、随机游走变体。

### 评分规则

- 判定阈值 `p ≥ 0.01` 通过；`0.01 ≤ p < 0.05` 计为「边缘」（算半分）；未通过不得分。
- `评分 = 100 × (可测项 − 未通过 − 0.5 × 边缘) / 可测项`，样本不足的项不计分。
- 结论：≥ 95 与真随机不可区分；≥ 80 整体随机；≥ 60 有一些可读规律；更低则规律明显。

**p 值怎么读**：p 值是「假如你的出招完全随机，单靠运气也能出现这么极端结果的概率」。所以 p 越大 = 越看不出异常（p = 0.40 表示随机的话有 40% 机会比这更夸张）；p = 0.005 表示随机的话只有 0.5% 的机会会这样，小到不太像巧合，于是判为「有规律」。判定线取 NIST 惯例的 0.01。p 值不是「你随机的概率」，也不是越大越好——只要不低于 0.01，这项就没抓到问题。

### 小样本方案与零分布标定

NIST 原本要求 ≥ 10⁶ 比特（约 50 万局），而实际对局远少于这个量级。为了让检测在各种样本量下都能给出**尽可能准确**的结果：

1. **参数按档位自动选择**：每个检验都有自己的候选档位和样本量要求，**从最标准的一档往下试**，取第一个满足要求的——样本充足时自动回到 NIST 原版参数：

| 检验 | 档位（由大到小） | 样本要求 |
| --- | --- | --- |
| 块内频率 | 块长 128 / 64 / 32 / 16 / 8 | ≥ 8 块 |
| 最长 1 游程 | NIST 三套参数表 M=10000 / 128 / 8 | ≥ 8 块 |
| 二元矩阵秩 | 32×32 / 16×16 / 8×8 / 4×4 / 3×3 / 2×2 | 32×32 需 38 个矩阵，其余 ≥ 8 个 |
| 模板匹配 | 模板 8 / 7 / … / 2 比特（整串统计） | 期望命中 ≥ 5 次 |
| 通用统计 | L = 6 / 5 / 4 / 3 / 2 | `(10·2^L + 8)·L` 比特 |
| 线性复杂度 | 块长 5000 / 1000 / 500 / … / 16 | ≥ 8 块 |
| 序列 / 近似熵 | 阶数 m = 2 ~ 4 | 随 `log₂n` 自适应 |
| 随机游走 ×2 | NIST 的「回到 0 循环」/ 固定窗口分段 | 循环数 < 500 时自动改用窗口 |

2. **零分布标定**（关键）：额外生成 **200 条同样长度、同样参数、同样编码**的真随机序列，用它们统计量的经验分布重新计算双边 p 值。这样做的效果是：
   - 自动抵消「每符 2 比特」编码本身的限制（4 个码字只用 3 个，`10` 不出现）；
   - 自动校正「取多个模板中最差」这类多重比较；
   - 自动吸收小样本下的近似误差。

   所以表中的 p 值是「**相对同条件下的真随机**」而言的。
3. **下限 64 局（128 比特）**：再少时几乎必然满分、没有参考价值，因此不提供检测。

### 实测

- 真随机 300 局 → **97/100**，16 项全部通过。
- 以 45% 概率重复上一招的 300 局 → **38/100**，9 项未通过（块内频率、游程、最长游程、DFT、模板匹配、通用统计、序列检验、近似熵、累积和）。

生成报告需 ~2 秒（200 次标定），弹窗会先显示进度提示。

## 存档

控制区右侧有「导出存档 / 导入存档」，用的是 **JSON**（`.rps` 文件，纯文本，可直接打开看或手改）：

```json
{
  "format": "rps-ai-save",
  "version": 3,
  "order": 3,
  "mode": "duel",
  "profiles": {
    "duel":   { "params": { "...": "…" }, "stats": {}, "hit": 0, "hitTries": 0, "ideal": {}, "history": "RPRS", "hitLog": "10" },
    "assist": null
  }
}
```

- `profiles` 里两种玩法各占一段（`null` = 该玩法还没启用过，导入后回到干净状态）。
- `history`：每局 2 个字符（我方出招 + 对手出招），如 `RSPRSS` 即 3 局 `✊vs✌️ / ✋vs✊ / ✌️vs✌️`；`hitLog` 每局 1 个字符（`1` / `0`，该局 AI 是否命中被预测者），用于「半衰期加权命中率」。
- `params`：`alpha / exploreScale / explore / autoTune / confidence / halfLife` —— 两种玩法的滑块与开关各自独立。
- **跨版本兼容**：读的时候只认自己认识的字段 —— 缺的用默认值补、多的直接忽略，所以新版存档交给旧版、旧版交给新版都能读（无非丢几个新字段）。
- **导出**：存成 `rps-当前模式-日期.rps`（如 `rps-assist-2026-10-07.rps`）下载到本地。
- **导入**：选该文件即可恢复 —— AI 会按各玩法自己的历史分别回放学习，当前模式、两套数据与参数一并还原。

## 文件结构

```
RPS-AI/
├─ index.html          页面结构（按顺序引入下列脚本）
├─ styles.css          样式
└─ js/
   ├─ core.js          基础库：招式常量、胜负判定、无偏随机、统计小工具
   ├─ predictor.js     预测核心：专家模型、学习、决策
   ├─ nist.js          NIST SP 800-22 随机性检测套件（15 项检验 + 数值函数）
   └─ app/
      ├─ context.js    应用上下文：常量、DOM 引用、状态、称谓、参数、双档案
      ├─ autotune.js   自动调参与显著性检验
      ├─ storage.js    存档序列化（构建 / 解析）
      ├─ render.js     全部界面渲染
      └─ main.js       对局流程、事件绑定、悬浮提示与启动
```
